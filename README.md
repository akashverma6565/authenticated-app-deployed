# TaskVault

A small authenticated task manager built with Node.js and Express. Users register, sign in, and can only see and change **their own** tasks.

**Live demo:** `<paste your Render URL here>`

## Features
- Registration and login with **hashed passwords** (bcrypt, cost 12; plain-text passwords are never stored)
- **Per-user data scoping**: every task query includes the signed-in user's id, so another user's task id matches nothing and returns 404
- Server-side sessions stored in Postgres, HttpOnly + SameSite cookies (Secure in production), session id regenerated on login
- CSRF token required on every POST
- Automated tests that prove password hashing and data isolation (`npm test`)

## Stack
Node.js, Express, PostgreSQL (`pg`), bcryptjs, express-session. Server-rendered HTML, no front-end framework.

## Run locally
Requires Node 18+.
```bash
git clone <this-repo-url>
cd taskvault
npm install
npm start          # http://localhost:3000
```
Without `DATABASE_URL`, the app uses an in-memory Postgres emulator, so data resets when you stop it. To use a real database locally, set `DATABASE_URL=postgres://user:pass@localhost:5432/taskvault` (add `PGSSL=disable` for a local server without SSL).

Run the tests: `npm test`

## Environment variables
| Name | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string (required in production) |
| `SECRET_KEY` | Long random string used to sign session cookies (required in production) |
| `NODE_ENV` | Set to `production` on the host |
| `PORT` | Provided by the host; defaults to 3000 |

## Deploy (Render free tier + free Postgres)
1. Create a free Postgres database (Neon, Supabase or Render) and copy its connection string.
2. Push this repo to GitHub.
3. On Render choose **New > Blueprint** and select the repo (it reads `render.yaml`), or create a Web Service with build `npm install --omit=dev` and start `npm start`.
4. Set `DATABASE_URL` to your connection string. `SECRET_KEY` is generated by the blueprint (or set your own). Tables are created automatically on first start.
5. Open the public URL, register two accounts, and confirm they can't see each other's tasks. Then paste the URL at the top of this README.

## Decisions
- **Postgres, not SQLite**: free hosts have ephemeral disks, so a file database would lose users on every restart.
- **bcryptjs** (pure JavaScript) instead of the native bcrypt module, to avoid build problems on hosts.
- **Ownership check inside the SQL** (`WHERE id = $1 AND user_id = $2`) so a forgotten check in app code can't leak data.
- **404 instead of 403** for other users' tasks, so ids can't be probed.
- **Logout is a POST** with a CSRF token, preventing forced logout from other sites.
- Kept scope small on purpose.
